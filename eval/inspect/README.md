# UK AISI `Inspect AI` Native Task Definition (`eval/inspect/`)

Provides a native [**UK AISI Inspect AI**](https://inspect.aisi.org.uk/) `@task` (`evergreen_insurance`) for the **Evergreen Insurance API Gym**, eliminating the Docker-in-Docker overhead of the METR wrapper by using Inspect's native multi-container Docker Compose sandbox (`sandbox=("docker", "../../docker-compose.yml")`) and Streamable HTTP MCP registration (`mcp_server_http(name="comm", url="http://localhost:3004/mcp")`).

---

## 1. Features

- **All 20 Scenarios (253 Tasks):** Dynamically loads Scenarios `01`–`20` (including the interactive multi-turn Scenarios `16`–`20`) from `eval/metr/tasks.json`.
- **Native 3-Modality Sandbox:** Connects directly to `docker-compose.yml` on the host and registers the Comm Hub MCP endpoint (`http://localhost:3004/mcp`) via `mcp_server_http`.
- **Decoupled 40/60 Scorer + Hard E&O Gate:** `evergreen_scorer()` invokes `bun eval/score.ts` and records `eo_compliant`, `trace_score`, `output_score`, and `api_calls` in Inspect's per-sample score metadata for `inspect view`.

---

## 2. Running Evaluations with `inspect eval`

```bash
# Run all realistic tasks with Gemini 3.8 Flash (workhorse model):
inspect eval eval/inspect/evergreen.py \
  --model google/gemini-3.8-flash

# Run Scenario 08 (E&O Trap Navigation) & Scenario 19 (Multi-Turn Claim Reversal) with Gemini 4 Argon:
inspect eval eval/inspect/evergreen.py \
  --model google/gemini-4-argon \
  -T scenario=08,19 \
  -T seed=realistic \
  -T difficulty=natural \
  -T modality_mode=strict

# Fast smoke run on Scenario 01 with Gemini 3.5 Flash Lite:
inspect eval eval/inspect/evergreen.py \
  --model google/gemini-3.5-flash-lite \
  -T scenario=01 \
  -T seed=clean \
  -T difficulty=explicit

# Launch the interactive Inspect trace & score viewer:
inspect view
```

## 3. LangChain Agent Harness (`evergreen_langchain`, ADR-005)

[`evergreen_langchain.py`](evergreen_langchain.py) is the harness for the first results run ([`DECISIONS.md`](../../DECISIONS.md), ADR-005). It runs one standard LangChain agent (`create_agent` over `ChatOpenAI(model="inspect")`) inside Inspect through Inspect's agent bridge, so every model takes the same path and Inspect supplies trials, token counts, limits, and logs. The agent gets typed tools only, with no shell and no generic HTTP tool:

- **REST:** one tool per operation in `specs/ams.yaml`, `rater.yaml`, `crm.yaml`, `ecm.yaml`, and `claims.yaml` (48 tools, named by `operationId`), generated by [`openapi_tools.py`](openapi_tools.py). Path and query parameters are tool arguments and the request body is a `body` argument. The tool layer fetches a client-credentials token (`agent-full`) from AMS, caches it, and sends it as a Bearer token.
- **Messaging hub:** the comm MCP tools over streamable HTTP (`/mcp` on `:3004`).
- **Carrier portals:** the Playwright MCP server (`@playwright/mcp@0.0.85`) over stdio, with headless system Chrome, an in-memory profile, and browser requests limited to the two portal origins. `browser_evaluate` and `browser_run_code_unsafe` are removed because they run arbitrary JavaScript.

Each sample resets the services for its seed with `POST /sim/reset` (which also clears the service-side trace), saves a before snapshot, runs the agent, collects the trace with `bun eval/collect-trace.ts`, saves an after snapshot, and scores with `bun eval/score.ts`. The score is the overall scenario score; its metadata holds `eo_compliant`, `trace_score`, `output_score`, `collateral`, the individual checks, and the directory with the trace, snapshots, and report (under the system temp directory; set `TMPDIR` to move it). Output checks read the live services, so a log cannot be rescored after the next sample has reset them.

All samples share one service stack, so they run one at a time: the task sets `max_connections=1` (which Inspect's default sample concurrency follows), and a lock held from reset to the end of scoring also serializes `--max-samples` above 1 and multi-model runs. The commands below pass `--max-samples 1` to make this explicit.

### Setup

```bash
pip install -r eval/inspect/requirements.txt   # in a Python 3.10+ virtualenv
# Node.js with npx (for the Playwright MCP server), bun, and Google Chrome.
# Chrome defaults to /usr/bin/google-chrome; override with EVERGREEN_CHROME_PATH.
MODALITY_MODE=strict bun run showcase   # all 8 services on :3000-:3007
```

The task checks `GET /sim/status` on every service and stops if the services do not run with the requested `modality_mode`. Service base URLs default to `http://localhost:3000` to `:3007`; `EVERGREEN_BASE_URLS='{"ams":"http://host:3000"}'` overrides any of them for the tools, resets, snapshots, and `eval/collect-trace.ts` (the output checks inside `eval/score.ts` still use the localhost defaults).

### Running

```bash
# Plumbing dry run: mockllm answers without calling a tool, so this runs reset, agent, trace
# collection, and scoring for a do-nothing agent. (mockllm counts tokens with tiktoken,
# which downloads its o200k_base encoding once.)
inspect eval eval/inspect/evergreen_langchain.py --model mockllm/model \
  -T scenario=01 --limit 2 --max-samples 1

# Gemini 3.8 Flash on Vertex AI (Application Default Credentials):
GOOGLE_GENAI_USE_VERTEXAI=true GOOGLE_CLOUD_PROJECT=<project> GOOGLE_CLOUD_LOCATION=<region> \
inspect eval eval/inspect/evergreen_langchain.py --model google/gemini-3.8-flash --max-samples 1

# Claude Sonnet 5.5 on Vertex AI:
ANTHROPIC_VERTEX_PROJECT_ID=<project> ANTHROPIC_VERTEX_REGION=<region> \
inspect eval eval/inspect/evergreen_langchain.py --model anthropic/vertex/claude-sonnet-5-5 --max-samples 1

# DeepSeek-V4.1-Flash through Vertex AI's OpenAI-compatible endpoint. The service name
# vertex-maas keeps these variables apart from VERTEX_BASE_URL and VERTEX_API_KEY, which
# the google provider also reads. When <region> is global, the host is
# https://aiplatform.googleapis.com (for regional endpoints, https://<region>-aiplatform.googleapis.com).
# The access token expires after an hour, so split longer runs (for example by scenario).
VERTEX_MAAS_BASE_URL=https://aiplatform.googleapis.com/v1/projects/<project>/locations/global/endpoints/openapi \
VERTEX_MAAS_API_KEY="$(gcloud auth print-access-token)" \
inspect eval eval/inspect/evergreen_langchain.py \
  --model openai-api/vertex-maas/deepseek-ai/deepseek-v4.1-flash-maas --max-samples 1
```

Task parameters match `evergreen_insurance` (`scenario`, `seed`, `difficulty`, `modality_mode`) plus `turn_limit` (model generations per sample, default 100). Pin model IDs and reasoning settings per run (for example `--reasoning-effort`).

### Tests

```bash
pytest eval/inspect/tests
```

The tests generate the tools from the real specs and check the operation count, parameter handling, auth header, and the per-sample pipeline with fake services, without network access or models.
